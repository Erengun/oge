# `oge resume` — re-enter a Run from its Ledger (#55, slice 1)

## Problem

A Run that parks at a Gate (unattended `errParked`) or stops interrupted
(Ctrl-C mid-Attempt or mid-Check) is permanent today: `oge resume` is a
`notYet` word, and nothing re-enters the walk. ADR-0012 specifies
resume-from-durable-state; the durable state already exists — the Ledger
records `RunStarted` (task + full `pipeline.Frozen` blobs),
`SnapshotTaken`, `OracleVersion` manifests, `AttemptStarting`
(start_revision, cause), `ProcessStarted`, `AttemptEnded`,
`CheckStarted/Ended` (full `oracle.Result`), `GateOpened` (pins +
choices), `GateDecided`, `RunParked`, `RunEnded`. What is missing is the
re-entry machine: nothing replays those records into `walk` state and
resumes the walk where it stopped.

## Scope of this slice

`oge resume <run-id>` covering three re-entry shapes:

1. **Parked at a real Gate** (`gate.result`, `gate.tamper`,
   `gate.bound_exhaustion`, `gate.ambiguous_file`): tail is
   `GateOpened` + `RunParked{gate}`. Rebuild the walk, rebuild the
   Request, verify its Pins equal the recorded `GateOpened.pins`
   (ADR-0012: resume never trusts what it cannot prove), then re-enter
   `w.decide`/`w.follow` so the human decides and the Run goes on.
   A second `GateOpened` with identical pins is truthful; a
   `RecResumed`/`RecRunResumed` record first makes the re-entry explicit.

2. **Interrupted mid-Check** (tail `CheckEnded{interrupted:true}` or
   `CheckStarted` with no end): a killed Check has no Verdict, so
   running it again is not a Recheck — re-run it as `check N+1` on the
   same `checked_tree` + manifest, then continue the normal walk.

3. **Interrupted mid-Attempt / crash** (`AttemptEnded{failure:
   "interrupted"}` tail, `RunEnded{Infrastructure stop}` with the same
   why, or `AttemptStarting` with no `AttemptEnded`): a fresh Attempt
   `attemptSpec{n: N+1, cause: "resume", start: start_revision}` —
   GLOSSARY already reserves cause `resume`. The Workspace is rebuilt
   by `repo.Checkout(start, ws)` like a send-back's.

## Explicitly refused (honest, recorded in the refusal message)

- Live runs (`run.Live(dir)`); already Accepted/Rejected/Cancelled
  (nothing to resume — point at `oge diff`/`oge apply`).
- Parked at `gate.held_out_conflict` / `gate.oracle_growth` (no
  `GateOpened`; those decisions aren't built — #46/#51).
- Chat-cut runs (their prep state is chat-owned) — refuse with a clear
  reason for now.
- Torn ledgers (`ledger.Open` refuses them; repair is the #54 decision).
- Ambiguous/unknown run ids: resume resolves a prefix against
  *resumable* runs only, refuses listing candidates.

## What this slice is NOT (later #55 slices)

- The `Interrupted` outcome + first-Ctrl-C semantics change (exit codes,
  TUI) — separate.
- `oge status` / `oge cancel` — separate.
- Full crash-recovery layering: process-identity records and escaped-
  process sweep at resume remain for the interrupted-status slice.
  Per-Run OS-released exclusive locks were pulled into this slice after
  adversarial testing reproduced concurrent resumes corrupting the Ledger.

## Design

`internal/run`:

- `Resume(ctx, p Params, dir string) (*Result, error)` in a new
  `resume.go`. `p` carries the runtime side (Agents, State, Version,
  Getenv, Observe, Gates) exactly like `Start`; `Repo`, `Task`, `Frozen`,
  `cut`, `Interactive` come from the Ledger, not args.
- `loadTail`: `ledger.Replay` the run dir; verify chain (hard error);
  rebuild `res` fields (ID, Started, Dir, Snapshot, Candidate, Oracle,
  Attempt count), `w` (`attempts`, `sendBacks`, `tamper`+`acked` from
  `GateDecided{choice:"acknowledge",tamper_ids}`, `promoted`/`resolved`
  from `AmbiguousResolved`, `check` = last `Verdict.check` or
  `CheckEnded.check`), and the tail shape.
- Tail dispatch:
  - gate tail → rebuild `a` (`&Attempt{ID: pins.Attempt, Candidate:
    pins.Candidate}`), `cr` (last `CheckEnded.result`), `m`/`mBlob`
    (manifest blob of `pins.Oracle`), `holds` (verdict + tamper +
    ambiguous replayed), `Route("check", holds, w.exhausted)` →
    sanity-check the edge leads to `pins.Gate`, then `w.request` and
    compare Pins — mismatch → Infrastructure stop ("durable state does
    not reproduce the Gate") — else `RecRunResumed` + `w.decide` →
    continue `w.follow`'s loop manually.
  - check tail → continue the loop at `check = N+1` with `a` rebuilt
    from `pins`/`AttemptEnded`, `resume = "check"`-like skip of QA
    (held-out manifest unchanged), fresh `control` for `m`.
  - attempt tail → `attemptSpec{n: attempts+1, cause: "resume",
    start: startRev}` → `repo.Checkout(start, ws)` → `implement()`.
- Re-entry uses the SAME walk code (`w.follow`, `implement`,
  `SplitCheck`) — no parallel resume path; the loop is entered with
  replayed `w`/`res`/`qa`/`m`. QA state (`qa.n`, `qa.added`) is rebuilt
  from verifier `AttemptStarting`s and `OracleVersion` records so
  version numbering never collides.
- `RecRunResumed` record: `{at: <seq>, gate|check|attempt: <where>,
  revision}` — written before any new effect (ADR-0012 written-ahead).

`internal/cli`:

- `oge resume <id>`: remove `resume` from `notYet`, dispatch to a
  `resumeCmd` that resolves the id (reuse `delivery.Find`-like listing
  against unfinished runs), opens state, builds `Env`-derived `Params`,
  reuses `selectView`/`v.show(ctx, in, start)` so both plain and TUI
  get the same progress/events and Gate ports (`renderer.gate` /
  `tui` decide).
- Non-TTY resume of a parked Gate reads the decision on stdin via the
  existing `renderer.gate`; EOF/no-decision → re-parks (truthful).

## Tests

- Unit: `loadTail` reconstruction per tail shape; pins mismatch →
  infra stop; refusal matrix (live/torn/cut/pseudo-gate/finished).
- `internal/run` e2e-ish: drive a Run to `errParked` (nil Gates port),
  then `Resume` with a scripted Gates port — assert the gate opens with
  the same pins, the decision continues the walk, and the ledger shows
  `Resumed` + `GateOpened`(same pins) + `GateDecided`.
- `internal/cli`: PTY/scripted — unattended run parks at gate.result;
  `oge resume` interactively takes "take" → Accepted; bad id → refusal;
  interrupted-mid-Check resume runs the Check again (no Verdict reuse).
- Torn ledger → refuse.

## Risks

- Rebuilding `holds`/`w.ambiguous` subtly different from the original
  walk would mis-route — mitigated by the Pins equality check before
  opening any Gate (a mismatch is an Infrastructure stop, not a wrong
  decision).
- `sendBackTurnFrom` re-derivation needs the last `CheckEnded.result` —
  stored in full; fine.
- Follow-up runs (`follow_ups`): `FollowUpRebased.start` is recorded;
  first-attempt resume uses it.

## Adversarial review findings (fixed before commit)

Two independent adversary passes — a semantic-equivalence auditor and a
diff reviewer — plus a 19-scenario monkey suite. Confirmed defects and
their resolutions:

- **Check off-by-one** (auditor D1): `dispatch` wants the check just run,
  not the next; `enter` passes `res.Checks` to dispatch-mediated tails.
  Pinned by a `[1 2]` check-number assertion.
- **Send-back counting** (D2/D3): replay counts `AttemptStarting{cause:
  "send_back"}` only — automatic and decided alike; a pending decision
  counts once via `dispatch` when its edge runs.
- **Review session state** (D4/D5/D6): `walk.reviewPromoted` replays the
  session flag; `resolve` re-enters `review` on the pinned Candidate's
  Attempt (`rt.impl`), restoring the `checked` pin.
- **Warmup** (D10, reviewer 2/3): the warm goroutine executes the Setup
  command, re-emits a missing `PreflightObserved`, and a failed Setup
  cancels the in-flight Attempt and ends the Run `Refused` — `loop`
  consults `ensureWarm` before the Attempt-failure arm, matching fresh
  ordering. `dir/cache-seed` and `dir/checks` are removed first, as the
  dead-Run sweeper does, so a SIGKILLed Run's stale trees can't fail the
  first resume.
- **EOF/no-decision on a resumed Gate re-parks** (reviewer 1): the walk
  writes `GateAbandoned` + `RunParked` (`walk.repark`) instead of an
  unresumable Infrastructure stop — per this plan's "EOF → re-parks".
- **Nil frozen Pipeline can't panic the live view** (reviewer 4): the
  CLI falls back to the plain view, and `Resume` still refuses cleanly.
- **Follow-up criteria replay** (reviewer 5): `taskFromBlob` re-applies
  each follow-up (`task.FollowUp`) so its acceptance criteria survive.
- **GateAbandoned after GateDecided refuses** — a decided Gate can't be
  abandoned; the durable decision must not be silently dropped.
- **Forge-proof pins** (monkey): `provePins` rebuilds the request from
  replayed state — forged `Attempt`/`Candidate`/`Checked` refuse.
- **Concurrent resumes exclude** (monkey): `live.lock` + `flock` (unix;
  `lockRun` nil elsewhere) — one winner, one "still running" refusal.
- **Partial review survives EOF** (continuation regression): abandoning a
  Gate pauses the review rather than resetting `reviewPromoted`; earlier
  promotions still require QA even if the remaining files are dropped.
- **Replay is inside the exclusive lock** (continuation): a second resume
  cannot reconstruct old state and apply it after another session advances
  the Ledger. Non-contention lock errors retain their actual cause.
- **Written-ahead resume precedes warmup** (continuation): prove Pins and
  append `Resumed` before spawning setup or deleting stale trees. Forged
  Pins refuse without warmup effects; missing implementer state refuses
  instead of dereferencing nil.
- **Prefix selection considers resumable Runs only** (continuation): an
  ended Run no longer makes a resumable prefix ambiguous; actual ambiguity
  lists candidate ids. Exact ids retain specific refusal diagnostics.

Accepted divergences: `cause:"resume"` on a re-run Attempt, a second
`CacheSeeded`/`ambiguous_review` Observation on re-entry (both records
are truthful about the resumed session), and receipt `Duration` measures
the resumed session (`res.Started` reset — the parked span isn't work).
